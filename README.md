# Helix Heresy

Helix Heresy is a desktop-focused static browser prototype about forbidden creature genetics, laboratory discovery, and questionable science.

The current build starts with slimes as the simplest creature type. Players edit 26-base genomes, synthesize living samples, discover traits through tests, manage slime reproduction, manage corpses and Suspicion, and assign creatures to early lab jobs.

For story background, long-term systems, current design direction, and open questions, see [DESIGN_BIBLE.md](DESIGN_BIBLE.md). The approved map projection, sprite scale, modular creature assembly, and readability rules live in [VISUAL_LANGUAGE.md](VISUAL_LANGUAGE.md).

## Running Locally

No build step is required.

Open `index.html` in a browser:

```bash
xdg-open index.html
```

Alternatively, serve the folder from VS Code's integrated Ubuntu terminal:

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000`. The game is currently designed for desktop play.

For development and automation on Ubuntu, install a current Node.js LTS release, run `npm install`, and use VS Code's integrated terminal. No VS Code extension is required. Run the Chromium correctness suite and map benchmark with:

```bash
npm run test:smoke
npm test
npm run test:visual
npm run benchmark:map
npm run benchmark:map:full
```

The smoke command is a quick cross-system check, but routine changes should run only the smallest focused test files or named cases that cover them. Do not run the complete suite automatically; reserve it for an explicit developer request. The visual command checks committed Ubuntu/Chromium baselines without changing them; use `npm run test:visual:update` only after deliberately reviewing an intended rendering change. The quick benchmark is intended for iteration; the full mode takes more samples. Timing budgets are advisory across different computers, while visible-count and idle-frame invariants fail the command.

## Saves

Helix Heresy stores a world/run library in browser `localStorage` and always opens to the title screen without materializing a run. Canonical worlds and mutable run records use separate namespaced records behind a storage adapter. A current generated world owns its stable ID, world seed, deterministic generated name, World Theme, playable year, exact authored definition IDs, and a compact canonical geodesic globe record including physical, arcane, resource, pristine-beast-ecology, pre-urban-humanity, population-backed pre-civic divinity, human religious knowledge, semantic faith, holy-site, Year 0 civilization origins, later city-foundation lineage, retained expansion failures, historical support corridors and bridges, initial and post-crisis physical support components, fortified-city, sovereign-city-polity, playable-year-beast-ecology, city-government, founding city-law, legal-amendment and temporary-directive history, offense-specific public-pressure history, offense-specific enforcement practice, six-stage qualitative justice throughput, cross-city-recognition, later religious-institution, non-state-network, orbital-internet, spaceflight, joint-stronghold, satellite-population, local-logistics, evacuation, ecological-crisis, temporary-coalition, infrastructure-condition, authoritative playable-year settlement, population, recovery, route-continuity, and physical-support-component facts, dated religious-institution condition, standing, successor, censure, displacement, and holy-site-custody history, and capability-gated non-state-network foundation, service, branch, affiliate, relationship, lifecycle, and collapse history. The mesh and compact pre-urban ranges are reconstructed deterministically while the world's generated arrays, feature records, settings, diagnostics, and digests remain saved facts. Older saved worlds may lack later facts and report that absence without being rewritten. Each run owns a separate ID and seed, scenario, starting-site record, mutable world-state branch, lifecycle, complete simulation state, and its saved themed opening selection.

New Run explicitly selects an existing world or generates one before beginning its first independent branch. Each current world provides a stable scenario-compatible starting-site catalog controlled by the world seed rather than the run seed. Chemistry Front offers fifteen candidates divided among city districts, protected approaches, and supported corridor fringes; a selected candidate records public tradeoffs and source digests in the run without occupying or altering the reusable catalog. The run then freezes its own validated Site Context: canonical selected-cell physical facts remain shared in origin, while parcel details and the starting calendar offset belong only to that run. The saved context supplies the current ambient environment, strategic inputs to coordinate-derived underground geology, cistern source and reserve, and physical service-head multipliers. World Library can start several runs from one world's untouched canonical state, resume any active branch, delete runs, and delete only worlds with no remaining run references. Continue selects the most recently played readable active run and shows both world and run metadata. A run has one autosaved roguelike timeline rather than rewindable save slots; an ended run remains a library record but is no longer a continuation.

JSON export produces a run bundle containing the run and its exact canonical world. Import validates the canonical digest, reuses an identical saved world, and remaps colliding IDs without overwriting different records. Obsolete single-continuation saves are intentionally not loaded because they have no authoritative world or World Theme.
